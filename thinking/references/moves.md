# Moves: design habits as reusable actions

Each move turns A into B, followed by an example. When ideating, apply a few moves to get new directions. When reviewing, use them to turn a sticking point into a proposal.

Moves are not rules. If one doesn't fit, try another, or combine two or three.

## Make people do one less thing

| Move | Turn… | Into… | Example |
|------|-------|-------|---------|
| Discover it | Things people must type (IP, path, account, format) | The system finds it; people just pick a name | A phone app finds the computer on the same Wi-Fi |
| Start on select | "Start", "Connect", "Apply" buttons | Picking starts it; next launch reconnects automatically | Pick the computer and it starts sending right away |
| Place it | Spoken or typed commands | Pick something up and put it somewhere; the position is the sentence | Assign a task by placing it on a board, not by describing it |
| Just ask the AI | Settings screens and manuals to learn | Say one sentence in a chat; the environment installs, features grow | Each person's tool grows from their own AI conversation |
| Check it at hand | Needing the full setup before seeing a result | Use the least equipment to see whether it moves | Preview the work on a phone before turning on the computer |

## Make the invisible visible

| Move | Turn… | Into… | Example |
|------|-------|-------|---------|
| Tune it on the thing | A row of sliders with English names | Tap the part on the work itself and adjust while watching | Tap a region of the picture and adjust it in place |
| Light it up | Status text, checkmarks, numbers | Brightness, color, shape show state and fitness | What you adjust glows; places that fit better glow brighter |
| Position is state | Lines of status text | Where something is and what shape it has, readable at a glance | A board where state is read from position and shape |
| Leave results on the map | Finished work vanishing into a folder | Results hang next to the task that made them | Finished pieces stay on the same map as their tasks |

## Give freedom, not limits

| Move | Turn… | Into… | Example |
|------|-------|-------|---------|
| Suggest, don't forbid | Only here, only this path | Go anywhere; brightness hints where fits best | Not "you can only drop on lit spots", but "lit spots fit better" |
| Move together | Taking turns, queues, step-by-step waiting | Human and AI act at once; one change and everything re-plans | No "whose turn is it" |
| Keep growing | A list that ends | A board that keeps growing; watch the frontier advance | A galaxy that keeps expanding outward |
| Two paths | Only a simple mode, or only a pro mode | Everyone gets the easy path; advanced people can open it up | Nodes for experts, layers for everyone else |

## Protect the work

| Move | Turn… | Into… | Example |
|------|-------|-------|---------|
| Track it separately | A pipeline that merges or averages away detail | Split the detail that would be lost and handle each part | Keep left and right separate so a one-sided gesture survives |
| Own stage | Performing inside someone else's software, under its limits | Build the critical stretch yourself; you decide how it looks | Write your own renderer so the work looks the way you made it |
| From file to stage | Delivering a file | Delivering something that opens and performs | Deliver something that works the moment it's opened, not a file plus instructions |
| Rigor guards the show | Tests that exist for technical metrics | Each safety net maps to a moment that must not fail in front of an audience | Reset cleanly on stop; restore before save |

## Find the meaning

| Move | Turn… | Into… | Example |
|------|-------|-------|---------|
| Walk downstream | Looking only at your own output | Follow the work downstream to the person who gets stuck | The stretch after the work is handed over |
| Efficiency into fun | Faster, stronger, more accurate | More fun, better feel, more sense of being in charge | The joy of directing AI, not the efficiency |
| Keep the feel | Copying a game's or metaphor's rules | Keep only the feeling; redesign the rules | Chess-like, but you don't need to know chess |
| Make it for yourself first | Building for an imagined "user" | Build it for yourself, then hand it to everyone | A personal tool that later becomes everyone's |
